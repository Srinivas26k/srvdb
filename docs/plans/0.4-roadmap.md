# SrvDB 0.4 roadmap

Status: proposed, 2026-11-23

## Goal

SrvDB 0.4 should match turbovec on compressed search (2 to 4 bits per
dimension, SIMD scans) and keep what turbovec lacks: durable storage,
delete and compact, HNSW/IVF indexes and filtered search. Every speed claim
must come from a committed, reproducible benchmark (AGENTS.md section 11).

Work branches start from `release/0.4`, cut from `release/0.3` after the
SQ8 fused-search branch is merged.

## Milestones

Each milestone is one GitHub issue, one work branch and one pull request
into `release/0.4`.

1. M0: merge `perf/sq8-fused-search`, cut `release/0.4`.
2. M1: benchmark harness (A1). Baseline numbers for SQ8, PQ, HNSW, IVF.
3. M2: checksums (E1). Lands before new formats so they carry checksums
   from day one.
4. M3: RaBitQ quantizer and rerank (B1, B3), with an ADR.
5. M4: SIMD fast-scan and dispatch (C1, C2), justified by M1 numbers.
6. M5: filtered HNSW (D1).
7. M6: Python API cleanup and adapters (F4, F1).
8. M7: should-have items, one issue each.

## Workflow per milestone

- Open an issue with scope, acceptance criteria and test plan.
- The owner agent implements it on a `feat/`, `perf/` or `fix/` branch.
- Gate: `cargo fmt`, `cargo clippy -- -D warnings`, `cargo test`, `pytest`.
- compliance-checker and security-auditor review the branch.
- Open a pull request that closes the issue. Commits follow Conventional
  Commits with no AI attribution lines.

## Out of scope and risks

- DiskANN/Vamana on-disk graph: a new index type that needs its own ADR;
  target 0.5.
- GPU, server mode, distributed features: excluded by AGENTS.md section 14.
- Each new on-disk format needs a version bump, an old-format reader and a
  migration test, which slows B1, B4 and E1.
- SIMD code needs `unsafe` with `// SAFETY:` comments and must match the
  scalar path within rounding.
- Benchmark datasets (SIFT, GloVe) are downloaded, never committed; their
  licences are checked first.

Reference: [turbovec](https://github.com/RyanCodrai/turbovec).
