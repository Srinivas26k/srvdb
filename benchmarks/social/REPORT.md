## Method

Each dataset is prepared in its own process (download, verify, L2-normalise, ground truth), then each mode is built from scratch in a separate process with `srvdb.create(path, dim, index=..., **options)`, fed in batches of 10,000 with default options, saved, and queried with `search_batch(queries, 10)`. Search bytes/vector is `db.memory_report()['vector_bytes'] / n`; disk columns divide the files in the database directory by n (files are preallocated past n, and RaBitQ keeps float32 vectors for rerank). Peak RSS is `ru_maxrss` of the mode's process and includes the benchmark's own copy of the vectors. 'No rerank' is RaBitQ after `set_rabitq_rerank(0)`.

## Key findings

Recall is recall@10 over the query set; bytes are search code bytes/vector.

- **High-dimensional LLM embeddings compress best.** On DBpedia OpenAI ada-002 (1536-d, 100k), RaBitQ 1-bit scans 200 B per vector instead of 6,144 B (30.7x smaller) at recall@10 0.9999 with default rerank; 2-bit 1.0000, 4-bit 1.0000.
- **Rerank is what keeps recall.** Without rerank RaBitQ 1-bit gives 0.7035 (DBpedia), 0.5859 (NYTimes), 0.2385 (GloVe). Rerank reads the float32 vectors RaBitQ keeps on disk, so its disk total per vector exceeds flat's (6,526 B vs 6,252 B on DBpedia). The saving is in what the scan reads and keeps hot, not in disk use.
- **Low dimensions hurt 1-bit codes.** GloVe-100 RaBitQ 1-bit: 0.7685; use 2-bit (0.9758, 33 B) or 4-bit (0.9999, 58 B). NYTimes-256 1-bit: 0.9469.
- **PQ is the weak spot (issue #95).** SrvDB PQ: 0.7882 (DBpedia), 0.5881 (NYTimes), 0.3927 (GloVe), 0.1235 (synthetic). Prefer RaBitQ until #95 is fixed.
- **SQ8 is a safe 4x:** 0.9963, 0.9768, 0.9765, 0.9637 (DBpedia, NYTimes, GloVe, synthetic).
- **Against FAISS and turbovec** (same data, queries, ground truth):
  - SrvDB RaBitQ with default rerank vs FAISS `IndexRaBitQ` + float32 refine at the same factor, 1-bit: DBpedia 0.9999 vs 1.0000; NYTimes 0.9469 vs 0.9395; GloVe 0.7685 vs 0.8298 (FAISS ahead on GloVe). Codes: DBpedia 1-bit 200 B vs 200.00 B.
  - Without rerank FAISS is higher: DBpedia 1-bit 0.8165 vs SrvDB 0.7035; SrvDB leans more on its rerank step.
  - turbovec (TurboQuant) 4-bit on DBpedia: 0.9572 at 788.62 B, no rerank; SrvDB RaBitQ 4-bit 0.9443 without rerank, 1.0000 with. turbovec cannot run GloVe-100 (dimension must be a multiple of 8).
  - Sign bits + float32 rerank (pgvector-style) is strong on DBpedia: 0.9994, but falls off at lower dimensions: NYTimes 0.8219, GloVe 0.5082.
  - FAISS PQ (M = dim/8) is also low: DBpedia 0.7153, GloVe 0.1819; PQ at these code sizes is weak in general, not only in SrvDB.
- **NYTimes flat recall is 0.9846, not 1.0.** The exact float32 scan disagrees with the ann-benchmarks ground truth on a few neighbours; NYTimes has many near-tied distances. Read compressed modes against this ceiling.
- **Crash safety reproduced locally:** 1,000 kill -9s across hnsw, churn, sq8, flat; every committed vector verified after reopen, 0 committed records lost.
- **Peak RSS** stays at or under 1,619.9 MiB per mode, including the benchmark's own copy of the vectors.
