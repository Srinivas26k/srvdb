SrvDB is built in the open. If you try it, we want to hear what worked, what
did not, and what you need next. Everything happens on GitHub.

## Ask a question

Post in
[Support & Help](https://github.com/Srinivas26k/srvdb/discussions/categories/support-help).
Include your OS, Python or Rust version, the SrvDB version and a short
snippet that shows what you tried.

## Share feedback

Tell us what you are building, what is missing, and how SrvDB compares with
what you use today in
[Tell us what you think of SrvDB](https://github.com/Srinivas26k/srvdb/discussions/65),
or start a thread in
[Community Feedback](https://github.com/Srinivas26k/srvdb/discussions/categories/community-feedback).
Critical feedback is as useful as praise.

## Request a feature

Discuss early ideas in
[Feature Requests](https://github.com/Srinivas26k/srvdb/discussions/categories/feature-requests).
When the idea is concrete, open a
[feature request issue](https://github.com/Srinivas26k/srvdb/issues/new/choose)
that describes the problem, not only the solution.

## Report a bug

Open a [bug report](https://github.com/Srinivas26k/srvdb/issues/new/choose)
with a minimal script that reproduces it. For data corruption, say whether
the process was killed or the machine lost power. Report security issues
privately, as described in
[SECURITY.md](https://github.com/Srinivas26k/srvdb/blob/master/SECURITY.md).

## Show what you built

Post your project in
[Project Gallery](https://github.com/Srinivas26k/srvdb/discussions/categories/project-gallery).
With your permission, projects shared there can be featured in these docs.

## Contribute or become a maintainer

Start with [Contributing](/srvdb/project/contributing/): setup takes a few
commands, and issues labelled `good first issue` point at the files involved.
Contributors who keep making careful, well-tested changes can be invited to
become maintainers; see
[How decisions are made](/srvdb/project/contributing/#how-decisions-are-made).
