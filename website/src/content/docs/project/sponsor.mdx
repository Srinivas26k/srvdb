## Why SrvDB matters

- **Embedded.** SrvDB is a library that runs inside your process. There is
  no server to deploy, no network port and no background service.
- **Offline.** The library never touches the network, so embeddings and
  documents stay on the machine that owns them.
- **Crash-safe.** Once `persist()` returns, committed data survives a process
  crash or power loss. Writes made after the last `persist()` can be lost.
  Every write path has a crash test.
- **Open.** Apache-2.0, with a Rust core and a Python API, installable with
  `pip install srvdb` or `cargo add srvdb`.

Local AI apps, such as private assistants, on-device RAG and agents that keep
their memory on disk, need a vector store that behaves like a file rather
than a service. SrvDB aims to be that store.

## What funding pays for

- **CI on more platforms.** ARM and Windows runners, so SIMD kernels and
  crash tests run on the architectures users have.
- **Benchmark hardware.** Dedicated, idle machines, so published numbers are
  reproducible and list hardware, OS, dataset, commit and command.
- **The roadmap.** The items in the
  [0.4 roadmap](https://github.com/Srinivas26k/srvdb/blob/release/0.4/docs/plans/0.4-roadmap.md):
  training-free quantization, SIMD fast-scan with runtime CPU dispatch,
  filtered search, checksums on vector pages and index files, fuzzing of the
  on-disk parsers, and LangChain and LlamaIndex adapters.
- **Docs and examples.** Guides, concept pages and runnable examples that are
  checked against the current code.
