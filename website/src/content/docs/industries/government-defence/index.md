Classified and isolated networks cannot use cloud AI at all.

## The challenge

- Doctrine, manuals and reports are scattered and hard to search.
- Systems must run with no internet access, ever.
- Every dependency has to be reviewed.

## Why SrvDB fits

- **Fully offline:** no network access, no telemetry, no background service.
- **Small, reviewable footprint:** one library, no Python runtime dependencies, Apache-2.0, a published SBOM with every release.
- **Crash-safe:** committed data survives power loss on field hardware.

## Five projects, five levels

Each project has its own page: the problem, how SrvDB powers it, what changes, architecture, use cases, core code and limits.

| Level | Project | What it does |
|---|---|---|
| 1 · Beginner | [Doctrine Assistant](/srvdb/industries/government-defence/doctrine-assistant/) | Air-gapped question answering over manuals and doctrine. |
| 2 · Intermediate | [Citizen Service Bot](/srvdb/industries/government-defence/citizen-service-bot/) | Answers citizens' questions from official public guidance. |
| 3 · Advanced | [Report Linker](/srvdb/industries/government-defence/report-linker/) | Links related reports and requests across departments. |
| 4 · Expert | [Field Intelligence Agent](/srvdb/industries/government-defence/field-intelligence-agent/) | An offline agent on rugged laptops combining text and imagery. |
| 5 · Frontier | [Sovereign AI Stack](/srvdb/industries/government-defence/sovereign-ai-stack/) | A fully reviewed, air-gapped AI stack with a published SBOM. |
