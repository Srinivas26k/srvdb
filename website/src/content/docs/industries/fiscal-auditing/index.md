Internal, external and public-sector auditors review ledgers, contracts, invoices and prior working papers.

## The challenge

- Prior-year findings and working papers are hard to reuse.
- Duplicate invoices and vendors hide behind different wording.
- Unusual journal entries are buried in volume.

## Why SrvDB fits

- **Working-paper and finding search** across engagements.
- **Duplicate candidates** for invoices and vendors by description similarity.
- **Unusual-entry flags:** descriptions far from typical ones.

## Five projects, five levels

Each project has its own page: the problem, how SrvDB powers it, what changes, architecture, use cases, core code and limits.

| Level | Project | What it does |
|---|---|---|
| 1 · Beginner | [Working-paper Search](/srvdb/industries/fiscal-auditing/working-paper-search/) | Search prior working papers and findings by meaning. |
| 2 · Intermediate | [Finding Drafter](/srvdb/industries/fiscal-auditing/finding-drafter/) | Drafts audit findings and management letters from similar past findings. |
| 3 · Advanced | [Duplicate Invoice Detector](/srvdb/industries/fiscal-auditing/duplicate-invoice-detector/) | Finds duplicate and near-duplicate invoices and vendors. |
| 4 · Expert | [Continuous Audit Agent](/srvdb/industries/fiscal-auditing/continuous-audit-agent/) | An agent monitoring entries and contracts continuously. |
| 5 · Frontier | [Public Funds Analytics](/srvdb/industries/fiscal-auditing/public-funds-analytics/) | Cross-entity pattern discovery for public-sector auditors. |
