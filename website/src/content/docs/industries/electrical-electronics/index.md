Electrical and electronics teams work from datasheets, schematics, test logs and compliance reports.

## The challenge

- The answer is on page 140 of a datasheet nobody remembers.
- Component shortages need fast, reliable substitutes.
- Bench and test logs pile up without being searchable.

## Why SrvDB fits

- **Datasheet and app-note Q&A** grounded in your own document library.
- **Substitute candidates** by similarity of specification text (an engineer verifies).
- **Test-log search and anomaly flags** by distance from normal logs.

## Five projects, five levels

Each project has its own page: the problem, how SrvDB powers it, what changes, architecture, use cases, core code and limits.

| Level | Project | What it does |
|---|---|---|
| 1 · Beginner | [Datasheet Q&A](/srvdb/industries/electrical-electronics/datasheet-qa/) | Ask questions of your component datasheets and get page citations. |
| 2 · Intermediate | [Second-source Finder](/srvdb/industries/electrical-electronics/second-source-finder/) | Suggests substitute components by specification similarity. |
| 3 · Advanced | [Test Log Analyzer](/srvdb/industries/electrical-electronics/test-log-analyzer/) | Finds similar past test failures and anomalous logs. |
| 4 · Expert | [Hardware Lab Agent](/srvdb/industries/electrical-electronics/hardware-lab-agent/) | An agent that remembers bench sessions, scope captures and decisions. |
| 5 · Frontier | [RF Fingerprint Lab](/srvdb/industries/electrical-electronics/rf-fingerprint-lab/) | Similarity search over RF spectrum fingerprints (research). |
