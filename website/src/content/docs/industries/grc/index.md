GRC teams map controls, policies, risks and evidence across many frameworks and regulations.

## The challenge

- The same control is documented differently for every framework.
- Questionnaires repeat questions already answered.
- Evidence gaps surface only during the audit.

## Why SrvDB fits

- **Control-mapping suggestions** by similarity between control texts (a person confirms).
- **Answer reuse** for security and vendor questionnaires.
- **Evidence gap checks:** controls with no close evidence item.

## Five projects, five levels

Each project has its own page: the problem, how SrvDB powers it, what changes, architecture, use cases, core code and limits.

| Level | Project | What it does |
|---|---|---|
| 1 · Beginner | [Policy Search](/srvdb/industries/grc/policy-search/) | Find the right policy passage from a plain question. |
| 2 · Intermediate | [Questionnaire Autopilot](/srvdb/industries/grc/questionnaire-autopilot/) | Answers security and vendor questionnaires from past approved answers. |
| 3 · Advanced | [Control Mapper](/srvdb/industries/grc/control-mapper/) | Suggests mappings between controls across frameworks. |
| 4 · Expert | [Regulatory Change Agent](/srvdb/industries/grc/regulatory-change-agent/) | Assesses which policies and controls a new regulation affects. |
| 5 · Frontier | [Continuous Compliance Platform](/srvdb/industries/grc/continuous-compliance-platform/) | On-prem AI retrieval for evidence, controls and audits with an audit trail. |

:::caution
SrvDB supports compliance work; it does not certify compliance with any framework.
:::
