How much memory does each SrvDB mode need per vector, and what recall
does it keep? Every number on this page is read at build time from
[`website/src/data/benchmarks/memory-recall.json`](https://github.com/Srinivas26k/srvdb/blob/master/website/src/data/benchmarks/memory-recall.json),
a copy of `benchmarks/social/results.json`. Nothing is typed by hand.
Speed is not measured here; it waits for an idle-machine run.

## What the columns mean

- **Search bytes/vector**: what a search scans per vector,
  `db.memory_report()["vector_bytes"] / n`. float32 for flat, codes otherwise.
- **Disk total/vector**: every file in the database directory divided by n.
  Files are preallocated beyond n, and RaBitQ keeps the float32 vectors on
  disk for exact rerank, so this is larger than the search bytes.
- **Recall@10**: against the dataset's ground truth (ann-benchmarks
  neighbours, or exact numpy search), default settings. "No rerank" is
  RaBitQ with `set_rabitq_rerank(0)`.
- **Peak RSS**: of the measuring process, including the benchmark's own
  copy of the vectors.

## Known weak spot: PQ

PQ recall is low on every dataset here (see the tables). This is tracked
in [issue #95](https://github.com/Srinivas26k/srvdb/issues/95); use RaBitQ
for compressed search until it is fixed.

## Reproduce

```bash
uv venv -p 3.12 .bench-venv
uv pip install -p .bench-venv/bin/python numpy matplotlib h5py pyarrow maturin
VIRTUAL_ENV=$PWD/.bench-venv .bench-venv/bin/maturin develop --release
.bench-venv/bin/python benchmarks/social/run.py
```

Datasets are downloaded by the benchmark script (never by SrvDB) into a
gitignored cache and verified by size and SHA256. See
[`benchmarks/social/README.md`](https://github.com/Srinivas26k/srvdb/blob/master/benchmarks/social/README.md)
and the full [report](https://github.com/Srinivas26k/srvdb/blob/master/benchmarks/social/REPORT.md).
